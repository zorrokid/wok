# Avian2D — Physics Reference

Covers the Avian2D (v0.5) physics engine as used in this project. Avian is a full rigid-body physics engine integrated with Bevy's ECS — physics bodies are just entities with the right components. Read this when working on player movement, collision, ground detection, or any feature involving physical simulation.

---

## Core Concepts

Avian handles gravity, collision detection, and velocity integration automatically. The key rule: **never manually apply gravity or write to `Transform` for movement.** Write to `LinearVelocity` only, and let Avian integrate it into position each physics step.

Avian's physics solver runs in `FixedUpdate`. However, **player movement systems should run in `Update`** (not `FixedUpdate`) when they read `keyboard.just_pressed()` — if placed in `FixedUpdate`, the system can run multiple times per frame and fire the jump impulse repeatedly for a single keypress.

## Key Components

### Rigid Bodies

```rust
RigidBody::Dynamic    // Affected by gravity and forces — player, enemies, crates
RigidBody::Static     // Immovable — walls, floors, platforms
RigidBody::Kinematic  // Moved by code, ignores forces — moving platforms, elevators
```

### Colliders

```rust
Collider::rectangle(width, height)         // Axis-aligned box
Collider::circle(radius)                   // Circle
Collider::capsule(half_length, radius)     // Capsule — preferred for characters (see below)
Collider::triangle(p1, p2, p3)             // Triangle
Collider::polyline(points, None)           // Line strip — generated by bevy_ecs_tiled
```

**Use `Collider::capsule` for player characters, not `Collider::rectangle`.** Rectangle colliders snag on tile corners when walking off platform edges — the flat bottom catches on the top corner of the last tile, holding the player up instead of letting them fall. A capsule's rounded ends slide off cleanly.

`Collider::capsule(half_length, radius)`:
- `half_length` — half the length of the straight cylindrical section
- `radius` — radius of the hemispherical end caps
- Total height = `2 * half_length + 2 * radius`
- Total width = `2 * radius`

### Velocity

```rust
LinearVelocity(Vec2)    // Velocity in world units/sec — write this to move entities
AngularVelocity(f32)    // Angular velocity in rad/sec
```

### Constraints

```rust
LockedAxes::ROTATION_LOCKED          // Prevent rotation — essential for player characters
LockedAxes::TRANSLATION_LOCKED_X     // Lock horizontal movement
GravityScale(f32)                    // Multiply global gravity: 0.0 = no gravity, 2.0 = double
```

### Material Properties

```rust
Friction::new(0.0)       // Friction coefficient — set to 0 to prevent sticking to walls
Restitution::new(0.0)    // Bounciness — 0 = no bounce, 1 = perfectly elastic
```

### Global Gravity

```rust
// Default is (0, -9.81). For pixel-space games, override to something larger:
app.insert_resource(Gravity(Vec2::new(0.0, -980.0)));
```

## Player Setup

A complete physics-based player entity:

```rust
// Capsule: half_length=2, radius=5 → total height=14px, width=10px
const COLLIDER_HALF_LENGTH: f32 = 2.0;
const COLLIDER_RADIUS: f32 = 5.0;

commands.spawn((
    Player,
    RigidBody::Dynamic,
    Collider::capsule(COLLIDER_HALF_LENGTH, COLLIDER_RADIUS),
    LockedAxes::ROTATION_LOCKED,     // Prevent tipping over
    LinearVelocity::ZERO,
    Friction::new(0.0),              // Prevent sticking to walls
    Restitution::new(0.0),           // No bouncing
    // Ground detection — see ShapeCaster section below
    ShapeCaster::new(
        Collider::capsule(COLLIDER_HALF_LENGTH, COLLIDER_RADIUS - 1.0),
        Vec2::ZERO,
        0.0,
        Dir2::NEG_Y,
    )
    .with_max_distance(10.0),
    ShapeHits::default(),
    Sprite::from_image(player_texture),
    Transform::from_xyz(spawn_x, spawn_y, 10.0),
));
```

## Ground Detection

`ShapeCaster` casts a shape from the entity's position in a direction each physics step and populates `ShapeHits` with the results. This is the correct Avian way to detect ground.

**How the shape cast works:**
The cast shape is placed at the given origin (entity-local space) and swept in the direction by `max_distance`. Crucially, the shape should be the **same size as (or slightly smaller than) the main collider** — not a thin strip. The shape already extends to the player's feet at `Vec2::ZERO`, and `max_distance` adds a buffer below. Using a thin shape at `Vec2::ZERO` would only cast as far as the shape's own extent and never reach the feet.

Use `SparseSet` storage on the `Grounded` marker because it is inserted and removed every frame:

```rust
// Marker component — present when ShapeCaster detects ground
#[derive(Component)]
#[component(storage = "SparseSet")]
pub struct Grounded;

// System: insert or remove Grounded based on ShapeHits each frame
fn update_grounded(
    mut commands: Commands,
    query: Query<(Entity, &ShapeHits), With<Player>>,
) {
    for (entity, hits) in &query {
        if hits.is_empty() {
            commands.entity(entity).remove::<Grounded>();
        } else {
            commands.entity(entity).insert(Grounded);
        }
    }
}
```

Run `update_grounded` before `player_movement` in the same schedule so the movement system sees the current grounded state:

```rust
app.add_systems(Update, (update_grounded, player_movement).chain());
```

## Movement Pattern

Write horizontal velocity from input; set vertical velocity only for jumps. Do not touch `velocity.y` for gravity — Avian handles that.

```rust
fn player_movement(
    keyboard: Res<ButtonInput<KeyCode>>,
    time: Res<Time>,
    mut query: Query<(&mut LinearVelocity, Has<Grounded>), With<Player>>,
) {
    let Ok((mut velocity, is_grounded)) = query.single_mut() else { return };

    velocity.x = if keyboard.pressed(KeyCode::ArrowRight) { MAX_SPEED }
                 else if keyboard.pressed(KeyCode::ArrowLeft) { -MAX_SPEED }
                 else { 0.0 };

    // Vertical: impulse on jump only — Avian applies gravity automatically.
    // Never set velocity.y every frame — that would fight gravity.
    if keyboard.just_pressed(KeyCode::KeyZ) && is_grounded {
        velocity.y = JUMP_VELOCITY;
    }
}

// Run in Update so just_pressed fires exactly once per player input.
app.add_systems(Update, (update_grounded, player_movement).chain());
```

## Collision Layers

Use collision layers to control which bodies interact with each other:

```rust
#[derive(PhysicsLayer, Default)]
pub enum GameLayer {
    #[default]
    Default,
    Player,
    Ground,
    Enemy,
}

// Player collides with ground only:
CollisionLayers::new(GameLayer::Player, [GameLayer::Ground])

// Ground collides with player and enemies:
CollisionLayers::new(GameLayer::Ground, [GameLayer::Player, GameLayer::Enemy])
```

Terrain colliders generated by `bevy_ecs_tiled` can be assigned a layer via `TiledPhysicsSettings`.

## Integration with bevy_ecs_tiled

When `TiledPhysicsPlugin::<TiledPhysicsAvianBackend>` is registered, it scans tile layers and generates `Collider` components on solid tile entities. The player's `Collider` then collides with terrain without any manual setup.

**Important:** `TiledPhysicsPlugin` only generates colliders for tiles that have collision shapes defined in the tileset's `.tsx` file. A tile with no `<objectgroup>` gets no collider — the player will fall through it. Define a full-tile collision rectangle in the tileset:

```xml
<!-- In tileset.tsx — add this inside <tileset> for each solid tile -->
<tile id="0">
  <objectgroup draworder="index" id="2">
    <object id="1" x="0" y="0" width="16" height="16"/>
  </objectgroup>
</tile>
```

`TiledPhysicsPlugin` creates `Collider` but does **not** add `RigidBody`. Attach an observer on the map entity to insert `RigidBody::Static` on each generated collider:

```rust
commands.spawn((TiledMap(map_handle), TilemapAnchor::Center))
    .observe(|ev: On<TiledEvent<ColliderCreated>>, mut commands: Commands| {
        commands.entity(ev.event().origin).insert(RigidBody::Static);
    });
```

See `docs/bevy-tiled.md` for how to configure which tile layers generate colliders.
